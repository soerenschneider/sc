sc is a command-line interface (CLI) tool, similar to the AWS CLI, designed as an interface for [soeren.cloud](https://github.com/soerenschneider/soeren.cloud).

## Installation

```shell
go install github.com/soerenschneider/sc@latest
```

```
Universal Command Line Interface for soeren.cloud

Usage:
  sc [command]

Available Commands:
  agent       Interact with a remote sc-agent instance
  completion  Generate the autocompletion script for the specified shell
  healthcheck Display a dashboard of the health of soeren.cloud
  help        Help about any command
  links       Manage bookmarks in Linkding
  logs        Interact with VictoriaLogs for querying and managing logs
  mpd         Control a Music Player Daemon
  pass        Interacts with the pass unix password store
  pw          Generate secure passwords
  qrcode      Encodes or decodes a string to/from a QR code.
  task        Taskwarrior helpers
  tf          Run terragrunt on the stacks of the soeren.cloud repository
  torrent     Commands for interacting with the Transmission torrent client
  update      Update sc to the latest release
  vault       Commands for interacting with HashiCorp Vault
  version     Print version and exit

Flags:
  -h, --help             help for sc
      --no-telemetry     Do not perform check for updated version
      --profile string   Profile to use
  -v, --verbose          Print debug logs

Use "sc [command] --help" for more information about a command.
```

## Profiles

Flag values can be stored in profiles in `~/.sc-profiles.yaml`. A profile is selected with `--profile` or the `SC_PROFILE` environment variable. Sections are named after the command path joined by dashes, e.g. `vault-login` for `sc vault login`. Each flag is taken from the most specific section that sets it, so settings of a parent command such as `mpd` apply to all its subcommands unless a more specific section overrides them. Flags given on the command line always take precedence.

```yaml
prod:
  mpd:
    address: music.lan:6600
  vault-login:
    username: jdoe
```

Some commands, such as `healthcheck`, read structured settings from their section, see their help for details.

## Code Generation

The `agent` subcommands are scaffolded using `cobra-cli` and use clients generated by `oapi-codegen` from [sc-agent's OpenAPI spec](https://github.com/soerenschneider/sc-agent/blob/main/openapi.yaml). They leverage the auto-generated libraries from [github.com/soerenschneider/sc-agent/pkg/api](https://github.com/soerenschneider/sc-agent/tree/main/pkg/api) to interact with the `sc-agent` REST API.
